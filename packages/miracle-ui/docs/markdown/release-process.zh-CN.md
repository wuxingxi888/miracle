# 发布流程

### 目标

Miracle UI 的版本发布以“稳定的小版本快迭代”为原则。每次 release 不只意味着发包，还意味着文档、示例和验证链路同步完成。

## 每次发布前必须完成

### 文档

-   README、首页或快速上手中涉及的接入口径已同步
-   新增能力对应的 README 或文档页已补齐
-   如有 API 变化，迁移方式已写明

### Demo

-   相关组件 demo 已更新
-   新增的场景页或模板说明可运行、可理解

### 测试

-   新行为有自动化测试覆盖
-   关键路径没有因为主题变量或暗黑模式而回归

### 发布说明

-   changelog 已明确本次变更类型
-   若存在破坏性调整，需显式标注影响范围与替代方案

### 推荐的变更分类

-   `feat`：新增功能
-   `fix`：问题修复
-   `docs`：文档更新
-   `test`：测试补充
-   `build`：构建、脚手架或发布流程调整
-   `refactor`：不改变外部行为的结构调整

### 当前阶段的成功标准

当前阶段不以“新增了多少组件”为唯一目标，更看重：

-   接入效率是否更高
-   场景覆盖是否更清晰
-   文档和模板是否更一致
-   版本发布后是否更容易被团队复用
